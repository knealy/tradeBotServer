## Issues Fixed

### 1. ✅ EventBus Start Method Error

**Error:**
```
ERROR - Bot execution failed: 'EventBus' object has no attribute 'start'
```

**Root Cause:**
- Two different `EventBus` implementations existed:
  - `events/event_bus.py` - Old implementation without `start()` method
  - `core/event_bus.py` - New implementation with `start()` method
- Trading bot was importing from wrong location and initializing twice

**Fix Applied:**

1. **Removed duplicate import** in `trading_bot.py`:
   ```python
   # OLD: from events.event_bus import EventBus, get_event_bus
   # NEW: # EventBus is imported where needed (core.event_bus)
   ```

2. **Removed duplicate initialization** (line ~363):
   ```python
   # OLD: self.event_bus = get_event_bus()
   # NEW: # EventBus is initialized in __init__ (line ~311)
   ```

3. **Made EventBus start optional** (line ~7275):
   ```python
   # Only start if event bus has start() method (for GUI support)
   if hasattr(self, 'event_bus') and self.event_bus and hasattr(self.event_bus, 'start'):
       try:
           await self.event_bus.start()
           logger.info("📡 Event bus started")
       except Exception as e:
           logger.warning(f"⚠️  Could not start event bus (not critical if GUI not running): {e}")
   ```

**Result:** Bot now starts successfully without EventBus errors. EventBus is optional and only needed when GUI is running.

### 2. ✅ Strategy Status Warning

**Error:**
```
WARNING - ⚠️  Strategy overnight_range is not active but should be running
```

**Root Cause:**
- `StrategyExecutor._check_strategy_status()` only checked for `is_running` attribute
- `overnight_range_strategy` uses `is_trading` attribute instead
- No unified interface for checking strategy status

**Fix Applied:**

1. **Updated `BaseStrategy`** (`strategies/strategy_base.py`):
   - Added `is_trading = False` initialization in `__init__`
   - Added `is_running` property that checks both `is_trading` and `status`:
   ```python
   @property
   def is_running(self) -> bool:
       """Check if strategy is currently running."""
       return self.is_trading or self.status == StrategyStatus.ACTIVE
   ```

2. **Updated `StrategyExecutor._check_strategy_status()`** (`core/strategy_executor.py`):
   ```python
   # Check for both is_running and is_trading attributes
   is_active = False
   if hasattr(strategy, 'is_running'):
       is_active = strategy.is_running
   elif hasattr(strategy, 'is_trading'):
       is_active = strategy.is_trading
   ```

**Result:** Strategy status checks now work correctly with all strategy implementations.

### 3. ✅ Risk Manager Missing Attributes

**Error:**
```
ERROR - Error in breakout monitoring: 'StrategyRiskManager' object has no attribute '_last_order_attempt'
```

**Root Cause:**
- `overnight_range_strategy` accessed `risk_manager._last_order_attempt` and `risk_manager.order_cooldown_seconds`
- These attributes didn't exist in `StrategyRiskManager`

**Fix Applied:**

Updated `core/risk_management.py`:

1. **Added `_last_order_attempt` dict** (line ~298):
   ```python
   # Track last order attempt time (flat dict format for strategy compatibility)
   # Format: {f"{symbol}_{side}": datetime}
   self._last_order_attempt: Dict[str, datetime] = {}
   ```

2. **Added `order_cooldown_seconds` property** (line ~317):
   ```python
   @property
   def order_cooldown_seconds(self) -> float:
       """Get default order cooldown in seconds (for backward compatibility)."""
       return self._default_cooldown
   ```

3. **Updated all risk check methods** to maintain `_last_order_attempt`:
   - When cooldown is active
   - When pending orders exceed limit
   - When position limits are reached
   - When recording order placement

**Result:** Strategy can now check cooldown status without AttributeError exceptions.
